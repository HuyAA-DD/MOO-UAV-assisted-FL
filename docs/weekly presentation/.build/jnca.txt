A B S T R A C T
This working document develops a UAV-assisted federated learning problem in which client
selection must account for complementary data, heterogeneous communication resources, and
incomplete information. Ground devices train locally, UAVs relay and aggregate updates, and
a coordinator selects participating devices and allocates bandwidth and computation resources.
Three objectives are considered: minimize population validation loss, total operational energy,
and elapsed training time. The document separates a reference simulator benchmark from an
implementable controller that only observes historical reports and explicitly acquired information.
Three algorithmic directions are specified: (A) set-aware multiobjective evolutionary scheduling,
(B) multi-fidelity evolutionary optimization with cost-aware evaluation and a verified Pareto
archive, and (C) optional adaptive probing with two-stage online recourse. Mathematical
assumptions, numerical examples, encodings, pseudocode, experimental controls, student
work packages, and verification exercises are provided. Evaluation fidelity is an optimization
mechanism; physical probing is a network action with its own cost. Proposed contributions and
hypotheses require empirical validation and further novelty assessment before journal submission.
1. System model and motivating learning scenario
1.1. Research question and scope
Consider geographically distributed sensors or cameras supported by UAV-mounted edge servers. Most clients
observe common conditions, while a few observe rare but important events. Good wireless channels do not necessarily
identify useful training data. Conversely, a large deviation from the average gradient can indicate useful minority
information or corrupted observations. The main research question is:
How can a scheduler select complementary clients and allocate wireless resources when evaluating candidate
schedules is expensive and current client information is only partially available?
The physical problem, learning objective, and optimization algorithm must remain distinct. A cheap proxy can guide
search but must not silently replace the population-level learning objective.
The initial model uses prescribed UAV movement, orthogonal spectrum pools, synchronous FL, fixed local SGD steps
and minibatch size, fixed uplink transmit power, and stationary datasets. Independent application offloading, optimized
flight trajectories, personalized models, and concept drift are extensions. Direction A establishes a reference-evaluated
scheduler; Direction B addresses search cost; Direction C introduces adaptive information acquisition. Students should
implement these layers sequentially.

six-client setting supports restricted enumeration and should be understood before increasing scale.

Within one snapshot, fixed local SGD work is independent of bandwidth and CPU if all selected clients finish. A

7.5. Offline versus online interpretation
Offline branching can evaluate many counterfactual schedules. A physical online controller generally cannot perform
full local training for many alternative sets without paying for it. The deployable version uses simulator-trained models,
permitted history, and charged probes; it executes one schedule and uses accessible feedback to update its predictor.
Online trial training, if used, is an actual operation and must appear in the operational ledger. If labels or validation
feedback are delayed, state the feedback delay and do not pretend instantaneous full validation is available. Monitor
calibration under deployment shift and define a fallback to a conservative feasible schedule when predictions become
unreliable.

9. Benchmark construction and experimental protocol
9.1. Research questions
RQ1: Does set-aware scheduling improve the loss–energy–time trade-off over channel-only and generic evolutionary
methods?
RQ2: Does multi-fidelity evaluation improve independently verified solution quality at equal actual search cost?
RQ3: Does adaptive probing improve complete FL episodes after its physical overhead is counted?
RQ4: Which regimes cause failures through rare-client exclusion, noisy data, stale reports, or fidelity rank reversal?
9.2. Scenario construction
The following are proposed starting configurations, not measured system specifications. Fix the total number of
training examples when varying client count, or label a growing-data study explicitly. Use independent data partitions
and mobility traces. Create paired scenarios moving the same rare-data client from a good to a poor channel, to isolate
statistical–physical coupling. State the class imbalance used in both target validation and test sets.
9.3. Baselines and fairness
Use three baseline groups:
1. Scheduling: random participation, channel greedy, an Oort-style utility policy, a gradient-diversity policy, and a
gradient-similarity policy. Identify adaptations rather than claiming exact reproductions.
2. Optimization: random feasible search, single-fidelity NSGA-II, a decomposition-based MOEA, and the same
proposed operators without multi-fidelity.
3. Information: no new probes, periodic probes, random probes, uncertainty-only probes, information-value probes,
and a fully observed oracle.
Deployable methods receive the same permitted information; extra statistics carry acquisition cost. The oracle is a
diagnostic comparator, not a fair deployable competitor. Use the same resource allocator when isolating client selection
and the same selection when isolating allocation.
Equalize actual optimizer time or profiled evaluation cost, not only fitness-call counts. Include cache construction,
model fitting, promotion, and reference audits. Match worker counts and hardware. Tune on separate scenarios; hold
out data partitions, mobility traces, and network sizes where practical.

9.4. Metrics and statistical reporting
For snapshot fronts, report reference-verified hypervolume using common normalization and a fixed dominated
reference point. Use IGD only with a credible common reference set; label a pooled empirical reference as approximate
and test sensitivity.
For complete FL runs, report final test loss/accuracy, macro-F1, rare-class recall, energy/time to a common accuracy
target, battery depletion, deadline violations, probe bytes and energy, and optimizer latency. Explicitly report runs that
do not reach the target. Under drift, measure time-integrated loss and recovery delay.
Use at least five independent seeds for pilot work and aim for ten or more paired runs for main comparisons, guided
by observed variance and compute cost. Report mean, dispersion, and paired confidence intervals. Tuning trials are not
independent test runs. Inspect full trajectories; final accuracy alone can conceal long periods of poor performance.
9.5. Ablations and failure diagnostics
• Set-dependent versus independent client scoring.
• Generic versus guided mutation; analytical versus evolved CPU allocation.
• Single fidelity versus fixed promotion versus adaptive promotion.
• Cross-fidelity calibration and exploration reserve on/off.
• No, periodic, uncertainty-only, and information-value probing.
• Full operational accounting versus deliberately omitted costs as a diagnostic only.
• One-round versus short-horizon search under equal compute budgets.
Measure fidelity rank reversals, prediction calibration across training stages, promotion cost per verified gain, and
rare/noisy client selection frequencies. Explain negative results, especially when one-round reference caching eliminates
the intended evaluation bottleneck.

10.4. Decision gates and contribution boundaries
Proceed to Direction B only if profiling shows an evaluation bottleneck and a useful fidelity hierarchy. Proceed
to Direction C only after the scheduler works with a fixed information set. If probing overhead exceeds its gains,
characterize when historical reports are sufficient.
Potential contributions include consistent information/resource modeling, set-aware operators, cost-aware fidelity
promotion with verified archives, and evidence about stale-information failure modes. These are proposed contributions,
not established novelty or convergence claims. The eventual paper must compare against the closest UAV-FL, client-
selection, and multi-fidelity optimization literature.
Recommended first experiment. Use two UAVs, six clients, fixed local work, and one initial checkpoint. Place
the rare-class client on a weak link, enumerate a restricted space, and measure true validation trade-offs. Compare
generic with set-aware search at equal reference cost. Introduce surrogate evaluation and adaptive probing only after
this controlled experiment is reliable.
